Security Transparency Repository

This overview provides insight into intended cryptographic designs, key derivation parameters, and brute-force defenses used in DinoVault.

01. High-Level Architecture

  • Client-side local encryption execution.
  • Zero-knowledge master password handling.
  • Cloud storage stores cipher-text data exclusively.
  • No backend master password recovery mechanism.

02. Cryptographic Primitives

Encryption Engine

XChaCha20-Poly1305 via Google Tink. Utilizes 256-bit keys and 192-bit nonces for authenticated encryption with data integrity protection.

Key Derivation (KDF)

PBKDF2 with HMAC-SHA256 using per-user random salt. Scales up to ~310,000 iterations on exported packages to mitigate offline brute-force attacks.

Brute-Force Mitigations

Enforced artificial delays, exponential lockout intervals following repeated failed attempts, and monotonic clock checks.

Memory Hygiene

Immediate wiping of character arrays, clearing derived keys upon vault locking, and cache purges on inactivity timeouts.
